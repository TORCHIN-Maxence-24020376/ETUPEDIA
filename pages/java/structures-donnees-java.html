Structures de données en Java

Les structures de données permettent de organiser et stocker l’information efficacement. En Java, on combine souvent la théorie (listes, piles, arbres…) avec le Java Collections Framework (List, Set, Map, etc.).

Voir aussi : UML — Analyse & conception • Algorithmes de tri en Java

Listes

Une liste est une suite ordonnée d’éléments, avec une position pour chacun. On peut insérer, supprimer, parcourir et chercher des éléments.

Listes chaînées vs tableaux dynamiques

  • Tableau dynamique (type ArrayList<T>) : accès par index en O(1), mais insertion/suppression au milieu coûteuse (décalage des éléments).
  • Liste chaînée (LinkedList<T>) : insertion/suppression en O(1) si on a déjà la référence au nœud, mais accès par index en O(n).
List<String> noms = new ArrayList<>();
noms.add("Alice");
noms.add("Bob");
noms.remove("Alice");

Piles et files

Ces structures contrôlent l’ordre de sortie des données :

  • Pile (stack) : LIFO (Last In, First Out) — on empile et dépile sur le même côté (ex : historique de navigation).
  • File (queue) : FIFO (First In, First Out) — le premier arrivé est le premier servi (ex : file d’impression).
Deque<Integer> pile = new ArrayDeque<>();
pile.push(1);    // empiler
pile.push(2);
int x = pile.pop(); // dépiler (2)

Arbres

Un arbre est une structure hiérarchique : un nœud racine, des nœuds enfants, etc. Un arbre binaire limite chaque nœud à au plus deux enfants. Les arbres de recherche binaires organisent les valeurs de façon à permettre une recherche plus efficace (en moyenne O(log n) si l’arbre est équilibré).

  • Parcours : préfixe (prefix), infixe (infix), postfix (postfix) — souvent implémentés récursivement.
  • Utilisations : index (arbres de recherche, arbres équilibrés), hiérarchies (menus, dossiers), interprétation d’expressions, etc.

Collections & interface Collection

Le Java Collections Framework fournit des interfaces génériques (Collection, List, Set, Queue, Map) et des implémentations (ArrayList, LinkedList, HashSet, HashMap, etc.).

  • Collection<E> : interface racine (ajout, suppression, taille, itération…).
  • List<E> : liste ordonnée indexée, peut contenir des doublons (ArrayList, LinkedList…).
  • Set<E> : ensemble sans doublons (HashSet, LinkedHashSet, TreeSet…).
  • Queue<E> : file ou file de priorité (Queue, Deque…).
Set<String> emails = new HashSet<>();
emails.add("a@exemple.fr");
emails.add("b@exemple.fr");
emails.add("a@exemple.fr"); // ignoré : pas de doublon

Maps : associer clés et valeurs

Une Map<K,V> associe une clé à une valeur (dictionnaire, table de hachage…). Les implémentations se distinguent par les garanties d’ordre et les performances.

  • HashMap<K,V> : très rapide en moyenne, pas d’ordre garanti, basé sur hashCode() / equals().
  • LinkedHashMap<K,V> : conserve l’ordre d’insertion.
  • TreeMap<K,V> : trié selon l’ordre naturel de la clé ou un comparateur (implémentation par arbre).
Map<String, Integer> scores = new HashMap<>();
scores.put("Alice", 12);
scores.put("Bob", 18);
int scoreBob = scores.get("Bob"); // 18

Bien choisir sa structure

  • Beaucoup d’accès par index → ArrayList.
  • Beaucoup d’insertion/suppression au milieu → LinkedList ou structure chaînée.
  • Besoin d’unicité → Set.
  • Association clé → valeur → Map (HashMap par défaut, TreeMap si ordre trié requis).
