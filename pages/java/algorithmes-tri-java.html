Algorithmes de tri en Java

Un algorithme de tri réorganise les éléments d’une liste selon un ordre (numérique, alphabétique, etc.). L’objectif est d’améliorer d’autres opérations (recherche, fusion…) en choisissant un algorithme adapté au contexte.

Voir aussi : Structures de données en Java • UML — Analyse & conception

Notions clés : complexité, stabilité, en place

  • Complexité en temps : comment le temps d’exécution évolue quand la taille des données augmente (notation Big-O).
  • Complexité en espace : mémoire supplémentaire nécessaire (en plus du tableau à trier).
  • Algorithme en place : ne requiert pas de tableau supplémentaire de taille proportionnelle à l’entrée.
  • Stabilité : préserve l’ordre relatif des éléments égaux.

Tris simples (O(n²))

Tri par sélection

Idée : à chaque itération, chercher le plus petit (ou plus grand) élément dans la partie non triée et le placer à la prochaine position libre. Simple, mais toujours en O(n²), même si le tableau est presque trié. 

public static void selectionSort(int[] tab) {
    int n = tab.length;
    for (int i = 0; i < n - 1; i++) {
        int min = i;
        for (int j = i + 1; j < n; j++) {
            if (tab[j] < tab[min]) {
                min = j;
            }
        }
        int tmp = tab[i];
        tab[i] = tab[min];
        tab[min] = tmp;
    }
}

Tri par insertion

Idée : on considère que le début du tableau est trié, puis on insère chaque nouvel élément à sa bonne place dans cette partie. Très efficace pour des tableaux presque triés (meilleur cas en O(n)), mais O(n²) dans le pire cas. 

public static void insertionSort(int[] tab) {
    for (int i = 1; i < tab.length; i++) {
        int x = tab[i];
        int j = i - 1;
        while (j >= 0 && tab[j] > x) {
            tab[j + 1] = tab[j];
            j--;
        }
        tab[j + 1] = x;
    }
}

Tri à bulles (bubble sort)

Parcourt le tableau et échange les voisins mal ordonnés, en répétant jusqu’à ce qu’il n’y ait plus d’échanges. Facile à comprendre mais généralement moins performant que l’insertion ou la sélection (O(n²) et grosses constantes).

Tris plus efficaces (O(n log n))

Tri fusion (merge sort)

Divise le tableau en deux moitiés, trie récursivement chaque moitié, puis fusionne les deux sous-tableaux triés. Complexité en temps O(n log n) dans tous les cas ; nécessite cependant un tableau auxiliaire de taille O(n). 

public static void mergeSort(int[] tab) {
    if (tab.length <= 1) return;
    int mid = tab.length / 2;
    int[] left = Arrays.copyOfRange(tab, 0, mid);
    int[] right = Arrays.copyOfRange(tab, mid, tab.length);
    mergeSort(left);
    mergeSort(right);
    merge(tab, left, right);
}

Tri rapide (quicksort)

Choisit un pivot, partitionne le tableau en deux parties (éléments < pivot, > pivot), puis trie récursivement les deux côtés. En moyenne, O(n log n), mais O(n²) dans le pire cas si le choix du pivot est mauvais.

Choisir le bon tri

  • Petit tableau, peu sensible aux perfs → tri par insertion ou sélection (simple à coder / comprendre).
  • Données très grandes → tri fusion ou quicksort (en moyenne O(n log n)).
  • Données quasi triées → tri par insertion fonctionne très bien.
  • Besoin de stabilité → tri fusion (dans son implémentation classique) est stable, quicksort ne l’est pas forcément.

Tri en Java : Arrays.sort et Collections.sort

En pratique, on utilise souvent les méthodes standard :

  • Arrays.sort(tab) pour les tableaux primitifs et d’objets.
  • Collections.sort(liste) (ou liste.sort(comparator)) pour les listes.

Les implémentations internes utilisent des variantes optimisées (par exemple TimSort pour les listes d’objets, mélange de tri fusion et insertion).
