Présentation

PL/pgSQL est le langage procédural de PostgreSQL. Il permet d'encapsuler des requêtes SQL avec des structures de contrôle (variables, conditions, boucles) et d'exécuter cette logique côté serveur. Objectifs : réduire les allers-retours client/serveur, garantir l'intégrité au plus près des données, mutualiser la logique.

Fonctions PL/pgSQL

Une fonction exécute de la logique côté serveur et retourne une valeur (scalaire, enregistrement ou table). Elle se crée avec CREATE FUNCTION et s'appelle via SELECT (ou dans d'autres requêtes SQL). Référence : CREATE FUNCTION.

Squelette minimal

-- Squelette d'une fonction PL/pgSQL
CREATE OR REPLACE FUNCTION nom_fonction(
  -- [argmode] [argname] argtype [DEFAULT expression], ...
)
RETURNS retour_type
LANGUAGE plpgsql
-- [IMMUTABLE | STABLE | VOLATILE]
-- [CALLED ON NULL INPUT | RETURNS NULL ON NULL INPUT | STRICT]
-- [SECURITY INVOKER | SECURITY DEFINER]
-- [PARALLEL SAFE | RESTRICTED | UNSAFE]
-- [COST n] [ROWS n] [SET param = value]
AS $$
DECLARE
  -- déclarations locales (ex. v_total integer := 0;)
BEGIN
  -- corps de la fonction (requêtes, IF/CASE, boucles, RAISE, etc.)
  RETURN /* expression du type "retour_type" */;
END;
$$;

Points clés de l'en-tête : volatilité (IMMUTABLE/STABLE/VOLATILE), gestion des NULL (STRICT ≃ RETURNS NULL ON NULL INPUT), sécurité (SECURITY DEFINER exécute avec les droits du créateur), et options d'exécution (COST, PARALLEL, SET).

Paramètres

  • Modes : IN (défaut), OUT, INOUT, VARIADIC (liste variable).
  • Valeurs par défaut : p_limite integer DEFAULT 10 → appel possible sans fournir l'argument.
  • Nommage : les paramètres sont adressables par leur nom dans le corps (p_id, p_code, ...).
CREATE OR REPLACE FUNCTION filtre_cours(p_min int DEFAULT 5)
RETURNS int LANGUAGE plpgsql AS $$
DECLARE v_cnt int; BEGIN
  SELECT COUNT(*) INTO v_cnt FROM Cours WHERE nb_places >= p_min;
  RETURN v_cnt;
END; $$;

-- Appels
SELECT filtre_cours();     -- utilise la valeur par défaut
SELECT filtre_cours(12);   -- surcharge

Retourner un record ou une table

Deux approches fréquentes : RETURNS TABLE(...) avec RETURN QUERY, ou RETURNS SETOF type.

-- a) RETURNS TABLE + RETURN QUERY
CREATE OR REPLACE FUNCTION liste_inscriptions(p_etu int)
RETURNS TABLE(cours_id int, note numeric)
LANGUAGE plpgsql AS $$
BEGIN
  RETURN QUERY
    SELECT i.cours_id, i.note
    FROM Inscriptions i
    WHERE i.etudiant_id = p_etu;
END; $$;

-- b) RETURNS SETOF <type composite>
-- Suppose un type composite Inscriptions (table ou type créé via CREATE TYPE)
CREATE OR REPLACE FUNCTION inscriptions_de(p_etu int)
RETURNS SETOF Inscriptions
LANGUAGE plpgsql AS $$
BEGIN
  RETURN QUERY SELECT * FROM Inscriptions WHERE etudiant_id = p_etu;
END; $$;

Déclarations, contrôle de flux et erreurs

CREATE OR REPLACE FUNCTION moyenne_cours(p_cours int)
RETURNS numeric LANGUAGE plpgsql AS $$
DECLARE v_moy numeric; BEGIN
  SELECT AVG(note) INTO v_moy FROM Inscriptions WHERE cours_id = p_cours;
  IF v_moy IS NULL THEN
    RAISE NOTICE 'Aucune note pour le cours %', p_cours;
    RETURN NULL;
  END IF;
  RETURN v_moy;
EXCEPTION WHEN division_by_zero THEN
  RAISE EXCEPTION 'Erreur de calcul';
END; $$;

Outils utiles : IF/ELSIF/ELSE, CASE, boucles FOR/WHILE, RAISE (DEBUG, NOTICE, WARNING, EXCEPTION), bloc EXCEPTION. Voir PL/pgSQL — structures.

Volatilité et performances

  • IMMUTABLE : même entrée ⇒ même sortie, sans I/O ni accès table (ex. fonctions purement mathématiques).
  • STABLE : peut lire mais pas modifier ; résultat constant durant une requête (idéal pour des lectures).
  • VOLATILE (défaut) : peut changer à chaque appel (séquences, now(), etc.).

Bien choisir la volatilité aide l'optimiseur. Voir Volatility Categories.

Sécurité et configuration

  • SECURITY INVOKER (défaut) : exécute avec les droits de l'appelant.
  • SECURITY DEFINER : exécute avec les droits du propriétaire (penser à fixer un search_path sûr : ALTER FUNCTION ... SET search_path = pg_catalog, public par ex.).
  • Paramètres de session : SET dans la définition pour figer un contexte (ex. SET role, SET timezone).

Exemple complet (commenté)

CREATE OR REPLACE FUNCTION demo_calcul_moyenne(
  p_cours_id int,
  p_seuil numeric DEFAULT 0
)
RETURNS numeric
LANGUAGE plpgsql
STRICT               -- NULL en entrée ⇒ NULL en sortie
STABLE               -- lecture seule, résultat stable durant la requête
SET search_path = pg_catalog, public
AS $$
DECLARE v_moy numeric; BEGIN
  SELECT AVG(i.note) INTO v_moy
  FROM Inscriptions i
  WHERE i.cours_id = p_cours_id AND i.note >= p_seuil;

  RETURN v_moy;
END; $$;

-- Appel
SELECT demo_calcul_moyenne(3, 10);  -- moyenne des notes ≥ 10

Procédures PL/pgSQL

Une procédure ne renvoie pas de valeur et s'exécute avec CALL. Elle vise les traitements opérationnels et le contrôle explicite des transactions (ouvrir/valider/annuler) dans le serveur. Référence : CREATE PROCEDURE.

Squelette minimal

CREATE OR REPLACE PROCEDURE nom_procedure(
  -- [IN | OUT | INOUT | VARIADIC] nom type [DEFAULT expr], ...
)
LANGUAGE plpgsql
-- [SECURITY INVOKER | SECURITY DEFINER]
-- [SET param = value]
AS $$
BEGIN
  -- corps (DML, validations, logs, etc.)
  -- possibilité de COMMIT / ROLLBACK à l'intérieur (cf. Transactions ci‑dessous)
END;
$$;

-- Appel
CALL nom_procedure(...);

Paramètres (IN / OUT / INOUT / VARIADIC)

Les procédures supportent les mêmes modes que les fonctions. Les paramètres OUT sont renvoyés comme résultat d'appel (selon le client).

CREATE OR REPLACE PROCEDURE maj_et_stats(
  IN p_cours int,
  IN p_note numeric,
  INOUT p_nbmaj int,
  OUT p_moy numeric
)
LANGUAGE plpgsql AS $$
DECLARE v_m numeric; BEGIN
  UPDATE Inscriptions SET note = p_note WHERE cours_id = p_cours;
  GET DIAGNOSTICS p_nbmaj = ROW_COUNT;  -- lignes modifiées

  SELECT AVG(note) INTO v_m FROM Inscriptions WHERE cours_id = p_cours;
  p_moy := v_m;  -- OUT
END; $$;

-- Appel
CALL maj_et_stats(3, 12.5, NULL, NULL);

Transactions dans une procédure

Les procédures peuvent exécuter COMMIT/ROLLBACK (et variantes ... AND CHAIN) quand elles sont au sommet de la pile d'exécution (pas dans une fonction appelée par SELECT). Penser aux savepoints pour isoler des lots. Voir Transaction Management. 

CREATE OR REPLACE PROCEDURE traitement_batch()
LANGUAGE plpgsql AS $$
BEGIN
  -- Lot A
  PERFORM etape_a();
  COMMIT;

  -- Lot B protégé
  BEGIN
    SAVEPOINT sp_b;
    PERFORM etape_b1();
    PERFORM etape_b2();
    RELEASE SAVEPOINT sp_b;  -- valide le lot B
  EXCEPTION WHEN others THEN
    ROLLBACK TO SAVEPOINT sp_b;  -- annule B seulement
  END;

  -- Fin
END; $$;

Erreurs et diagnostics

  • GET DIAGNOSTICS var = ROW_COUNT; : nombre de lignes affectées par la dernière commande DML.
  • Utiliser RAISE pour consigner (NOTICE/WARNING) ou interrompre (EXCEPTION).

Triggers

Un trigger attache une fonction à un événement (INSERT, UPDATE, DELETE, TRUNCATE), en BEFORE ou AFTER, au niveau ROW (par ligne) ou STATEMENT (une fois par commande). Références : Trigger Functions, CREATE TRIGGER.

Squelette

-- Fonction de trigger
CREATE OR REPLACE FUNCTION trg_nom()
RETURNS trigger AS $$
BEGIN
  -- TG_OP (INSERT/UPDATE/DELETE), NEW/OLD, TG_TABLE_NAME, TG_WHEN, TG_LEVEL, TG_ARGV[n]
  RETURN NEW; -- pour BEFORE/ROW ; RETURN OLD dans certains DELETE ; RETURN NULL pour ignorer la ligne
END;
$$ LANGUAGE plpgsql;

-- Déclaration du trigger
CREATE TRIGGER nom
BEFORE UPDATE OF col1, col2 ON ma_table
FOR EACH ROW
WHEN (NEW.col1 IS DISTINCT FROM OLD.col1)  -- filtre côté trigger
EXECUTE FUNCTION trg_nom();

Statement‑level & tables de transition

Les triggers STATEMENT ne voient pas NEW/OLD, mais peuvent référencer toutes les lignes affectées via tables de transition (REFERENCING NEW TABLE AS nt OLD TABLE AS ot), pratique pour des réconciliations. 

CREATE OR REPLACE FUNCTION trg_verif_batch()
RETURNS trigger LANGUAGE plpgsql AS $$
DECLARE r record; BEGIN
  -- parcourir toutes les nouvelles lignes de l'instruction
  FOR r IN SELECT * FROM nt LOOP
    -- validations globales possibles ici
  END LOOP;
  RETURN NULL; -- STATEMENT level
END; $$;

CREATE TRIGGER verif_batch
AFTER UPDATE ON Inscriptions
REFERENCING NEW TABLE AS nt
FOR EACH STATEMENT EXECUTE FUNCTION trg_verif_batch();

Déclencheurs contraints (déférables)

Les constraint triggers peuvent être DEFERRABLE et évalués en fin de transaction (utile pour des règles croisées complexes). 

CREATE CONSTRAINT TRIGGER verif_coherence
AFTER INSERT OR UPDATE ON Inscriptions
DEFERRABLE INITIALLY DEFERRED
FOR EACH ROW EXECUTE FUNCTION trg_nom();

Exemple générique « journalisation »

CREATE TABLE log_chg (
  at timestamptz DEFAULT now(),
  t text, op text, id int, old jsonb, new jsonb
);

CREATE OR REPLACE FUNCTION trg_log()
RETURNS trigger AS $$
BEGIN
  INSERT INTO log_chg(t, op, id, old, new)
  VALUES (TG_TABLE_NAME, TG_OP,
          COALESCE(NEW.id, OLD.id),
          to_jsonb(OLD), to_jsonb(NEW));
  RETURN COALESCE(NEW, OLD);
END; $$ LANGUAGE plpgsql;

CREATE TRIGGER log_all
AFTER INSERT OR UPDATE OR DELETE ON Etudiants
FOR EACH ROW EXECUTE FUNCTION trg_log();

Bonnes pratiques

  • Intégrité d'abord : PK/FK/CHECK et contraintes au niveau schéma avant les triggers.
  • Lisibilité : nommer les fonctions/paramètres clairement, documenter signatures et effets de bord.
  • Volatilité adaptée (IMMUTABLE/STABLE/VOLATILE) pour aider l'optimiseur.
  • search_path explicite en SECURITY DEFINER pour éviter des résolutions de schéma dangereuses.
  • Diagnostics : utiliser GET DIAGNOSTICS ... ROW_COUNT, et journaliser les opérations sensibles.
  • Éviter les boucles de triggers : conditions WHEN, IS DISTINCT FROM, et drapeaux.
  • Préférer FOR .. IN SELECT aux curseurs quand c'est possible (plus simple/rapide).

Exceptions & gestion d'erreurs

Exceptions & gestion d'erreurs

On peut intercepter des erreurs avec un bloc EXCEPTION (cf. doc PL/pgSQL « Control Structures »).

BEGIN
  -- opérations potentiellement fautives
EXCEPTION WHEN unique_violation THEN
  RAISE NOTICE 'doublon détecté';
  -- traitement alternatif
WHEN others THEN
  RAISE; -- relancer
END;

Erreurs typiques : unique_violation, foreign_key_violation, division_by_zero, etc. Voir Trapping Errors.

Curseurs

Les curseurs permettent un traitement ligne-à-ligne quand c'est nécessaire (préférer les boucles FOR .. IN SELECT quand possible).

DO $$
DECLARE c refcursor; r record; BEGIN
  OPEN c FOR SELECT id, titre FROM Cours ORDER BY id;
  LOOP
    FETCH c INTO r; EXIT WHEN NOT FOUND;
    -- traiter r.id, r.titre
  END LOOP;
  CLOSE c;
END $$ LANGUAGE plpgsql;

Voir : PL/pgSQL — Cursors.
