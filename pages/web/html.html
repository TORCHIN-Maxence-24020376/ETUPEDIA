HTML : bases & structure

HTML (HyperText Markup Language) donne du sens au contenu. Un HTML bien structuré améliore l’accessibilité, le référencement et la maintenabilité. Les sections ci-dessous couvrent la structure, les balises sémantiques, le texte/média et les formulaires accessibles.

Voir aussi : CSS • JavaScript

Structure minimale d’un document

Un squelette propre, prêt pour un site responsif :

<!doctype html>
<html lang="fr">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Titre de la page</title>
</head>
<body>
  <header>...</header>
  <main>Contenu principal</main>
  <footer>...</footer>
</body>
</html>

Balises sémantiques clés

  • <header>, <nav>, <main>, <article>, <section>, <aside>, <footer> : donnent le rôle des zones.
  • Hiérarchie des titres : un seul h1 logique, puis h2, h3… (pas de saut arbitraire).
  • Texte : <p>, <strong>, <em>, citations <blockquote>, code <code>.

Exemple structuré

<article>
  <header>
    <h1>Comprendre la sémantique</h1>
    <p>Mise à jour <time datetime="2025-11-10">10/11/2025</time></p>
  </header>

  <section>
    <h2>Pourquoi c'est important ?</h2>
    <p>La sémantique aide le SEO, les lecteurs d'écran et les outils d'indexation.</p>
  </section>

  <footer>Rédaction : <a href="#" rel="author">Équipe ETUPEDIA</a></footer>
</article>

Texte, images et liens accessibles

  • Images : texte alternatif utile (pas décoratif), <figure> + <figcaption> pour légender.
  • Liens descriptifs (“Voir le tutoriel HTML”) plutôt que “Clique ici”.
  • Préférer textContent à innerHTML côté JS quand il y a des données utilisateur.
<figure>
  <img src="/assets/img/logo-og.png" alt="Logo ETUPEDIA">
  <figcaption>Logo officiel d'ETUPEDIA</figcaption>
</figure>

Formulaires accessibles (A11y)

  • Relier chaque <label> à un id d’input.
  • Utiliser les bons type (email, date, number, etc.), required, et messages d’erreur clairs.
  • Regrouper avec <fieldset> / <legend> si nécessaire.
<form>
  <fieldset>
    <legend>Newsletter</legend>
    <label for="email">Email</label>
    <input id="email" name="email" type="email" required>
    <button>S'inscrire</button>
  </fieldset>
</form>

Référencement & partage avancé (SEO, Open Graph, Twitter Cards)

Ces métadonnées aident les moteurs et les réseaux sociaux à présenter correctement ta page.

Balises SEO essentielles

  • Titre unique et pertinent (≈ 50–60 caractères).
  • Méta description claire (≈ 150–160 caractères), sans keyword stuffing.
  • Canonical : URL de référence si le contenu existe à plusieurs adresses.
<title>HTML — bases, structure & SEO avancé</title>
<meta name="description" content="Structure sémantique, formulaires accessibles, Open Graph, Twitter Cards.">
<link rel="canonical" href="https://exemple.com/pages/web/html.html">

Open Graph (Facebook, LinkedIn, Discord…)

Permet d’afficher un beau “aperçu” (titre, description, image) quand on partage un lien.

<meta property="og:locale" content="fr_FR">
<meta property="og:site_name" content="ETUPEDIA">
<meta property="og:type" content="article">
<meta property="og:title" content="HTML — bases, structure & SEO">
<meta property="og:description" content="Du HTML sémantique au partage social.">
<meta property="og:url" content="https://exemple.com/pages/web/html.html">
<meta property="og:image" content="https://exemple.com/assets/img/logo-og.png">
<meta property="og:image:alt" content="Logo ETUPEDIA">

Twitter Cards

Très similaire à OG. Le type le plus courant pour un article est summary_large_image.

<meta name="twitter:card" content="summary_large_image">
<meta name="twitter:title" content="HTML — bases, structure & SEO">
<meta name="twitter:description" content="Structure sémantique, OG/Twitter.">
<meta name="twitter:image" content="https://exemple.com/assets/img/logo-og.png">
<meta name="twitter:image:alt" content="Logo ETUPEDIA">

Bonnes pratiques SEO supplémentaires

  • Un seul h1 logique, titres hiérarchisés.
  • Images : poids optimisé, attributs width/height, alt descriptif.
  • Liens internes cohérents (maillage), balises <nav> et aria-label si besoin.
  • Pas de contenu dupliqué ; utiliser la balise canonical si nécessaire.
